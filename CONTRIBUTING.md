# Una comunidad abierta a mejoras

Esta es una primera contribución: si una persona la descarga y le sirve, ya cumplió un objetivo. Son bienvenidas correcciones, ideas, documentación, pruebas, accesibilidad, traducciones y adaptadores seguros. No hace falta ser experto ni aportar código.

El repositorio es público y acepta issues y pull requests. El contenido sigue siendo preliminar: esto no anuncia una release estable ni una integración operativa entre Dots. También podés aportar sin código contando el resultado de la primera prueba del taller descrita en el README. No existe obligación de registrarte ni de informar tu uso.

## Proponer una mejora o informar un error

1. Revisá README, ROADMAP e issues existentes para evitar duplicados.
2. Abrí un issue con título concreto, problema que querés resolver, pasos de reproducción y resultado esperado. Indicá navegador/sistema y versión de n8n si corresponde.
3. Adjuntá un ejemplo pequeño con datos ficticios. Nunca incluyas secretos, datos personales, URLs privadas ni exports reales con credenciales.
4. Para un cambio grande, discutí el enfoque antes de implementarlo. No es una promesa de aceptación ni de fecha.

## Aportar mediante Pull Request

1. Hacé un fork y creá una rama para una sola mejora.
2. Conservá el modo demo sin servicios externos activados por defecto.
3. Agregá o ajustá pruebas para la lógica modificada y ejecutá `npm test`.
4. Documentá límites, permisos, costos y licencias. Si probaste en navegador o n8n, indicá versiones y pasos; no marques pruebas que no realizaste.
5. Abrí una PR explicando qué cambia, qué no cambia, cómo lo probaste y cualquier riesgo pendiente. Relacioná el issue si existe.
6. Esperá revisión del mantenedor. No se fusionan cambios automáticamente ni se promete plazo de respuesta.

Aportá solo material que tengas derecho a compartir bajo la licencia del proyecto. No añadas binarios, modelos grandes, telemetría, personajes de terceros ni workflows de producción. La licencia del proyecto no cambia las licencias de n8n o de otras dependencias.

Para incidentes que involucren información sensible, seguí SECURITY.md y no uses un issue público para revelar el contenido. Respetá CODE_OF_CONDUCT.md.

## Gestión

Consultá [GOVERNANCE.md](GOVERNANCE.md). Dots–Jarvis coordina el mantenimiento con revisión; las contribuciones comunitarias siguen abiertas y no se ejecutan ni fusionan automáticamente.

# Gestión del proyecto

**Espacio para Agentes Dots+N8N** es un proyecto comunitario gestionado con asistencia de **Dots–Jarvis**, por encargo del propietario de este repositorio.

Dots–Jarvis coordina propuestas, desarrollo, pruebas y documentación con herramientas de IA. No es una organización independiente ni un servicio oficial de OpenAI, Microsoft o n8n. Su disponibilidad y sus acciones dependen de las herramientas, permisos y sesiones disponibles. No prometemos operación continua, respuesta inmediata ni mantenimiento ilimitado.

## Una comunidad abierta

Cualquier persona puede sugerir mejoras, reportar errores y enviar pull requests. La gestión centralizada no cierra las contribuciones: las propuestas se revisan antes de incorporarlas. No se otorga acceso de escritura a terceros por abrir un issue o una PR. No se fusionan ni ejecutan contribuciones automáticamente.

El propietario conserva el control del repositorio y puede cambiar prioridades, detener trabajo o revocar accesos. Dots–Jarvis mantiene el proyecto dentro del alcance autorizado; decisiones sobre gastos, permisos, credenciales o acciones sensibles requieren la autorización aplicable.

## Cómo se decide

1. Un problema reproducible y pequeño tiene prioridad sobre añadir funciones decorativas.
2. Cada cambio debe describir utilidad, alcance, pruebas, limitaciones y reversión cuando corresponda.
3. Antes de publicar se revisan datos privados, licencias, dependencias y cambios de permisos.
4. Los estados demo, experimental y probado deben quedar visibles. Una prueba simulada no se anuncia como integración real.
5. Las versiones y cambios se documentan en el repositorio. Las ideas de ROADMAP no son promesas de fecha.

## Privacidad por defecto

No se publican conversaciones, documentos personales o empresariales, bóvedas privadas, identificadores de cuentas, credenciales, endpoints internos ni exports de producción. Ejemplos, capturas y grafos usan datos sintéticos. El grafo visual no es una copia ni una conexión a una bóveda privada de Obsidian.

No hay telemetría ni envío a servicios externos por defecto. Cualquier integración futura debe explicar qué información sale, a dónde, con qué permiso y costo. Nunca incluir secretos en el frontend.

## Qué significan las métricas

Estrellas, forks, clones y descargas son señales distintas. No prueban usuarios únicos ni uso efectivo. Las descargas de un archivo de release no representan todas las descargas del código. Las métricas agregadas no identifican personas; se informarán con sus límites y sin rastreo individual.

## Reportes y seguridad

Usá Issues para preguntas o fallos con datos ficticios. No publiques secretos ni información sensible. Consultá SECURITY.md para el mecanismo privado disponible; si todavía no está habilitado, solicitá un canal privado sin describir públicamente la vulnerabilidad.
